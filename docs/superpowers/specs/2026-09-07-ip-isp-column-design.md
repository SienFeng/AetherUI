# 来源 IP 运营商列 设计文档

日期：2026-09-07
状态：待评审

## 1. 背景与目标

入站列表的展开行已经能对每个来源 IP 显示归属地（「中国 山东省 聊城市」），但看不到**运营商**。管理员实际需要它回答两类问题：

> 这个用户是电信还是联通？（线路质量与节点选择的排查起点）
> 这个来源 IP 是不是机房？（把账号挂在服务器上中转或转卖的强信号——一个「United States · Amazon」的来源 IP 与一个「山东 电信」的来源 IP，含义完全不同）

目标是在展开行的「归属地」旁新增一列「运营商」，并在访问日志弹窗的来源列表里同步显示。

### 非目标

- 不引入在线 IP 查询接口。那会把用户的来源 IP 发给第三方，与本项目全离线库的取向冲突，且有限速与可用性问题。
- 不引入第三个数据源。现有两个源的 ISP 数据都是现成的（见 §2）。
- 不做基于 ISP 的分流、限速或封禁。本次只做展示。
- 不改动地区限制（geo dat 生成）与共享检测的任何行为。

## 2. 现状核实

**两个数据源都带 ISP，代码里都显式丢弃了。**

ip2region 的 `ipv4_source.txt` 是 7 字段，第 6 字段就是运营商：

```
1.0.1.0|1.0.3.255|中国|福建省|福州市|中国电信|CN
123.171.0.0|123.171.63.255|中国|山东省|聊城市|电信|CN
```

而 `util/ipdb/ipdb.go` 的 `parseIP2Region` 校验字段数为 7，却只取 fields[2..4]。

纯真库的每条记录是「国家字符串 + 地区字符串」两段，第二段就是运营商。`util/qqwry/qqwry.go` 的 `toRecord` 里写着：

```go
_ = area // ISP 信息本包不保留，与 ip2region 那一路口径一致
```

**阻碍在 `bin/*.dat` 的自定义紧凑格式**：`ipdb.Location` 只有 Country/Region/City，`locationSize = 6`（三个 uint16 字符串池下标），`formatVersion` 硬编码为 1，`Parse` 见到版本不符直接报错。

`ipdb.go` 顶部的注释预判了加 ISP 的代价：

> 精度取舍：境外只保留国家，中国保留到省+市。上游把同一个城市按 ISP 拆成多段，
> 而本包不存 ISP，因此相邻同归属地的段会被合并掉。

这个预判在中国段上**不成立**，在境外段上**成立且严重**。实测见 §4.3。

## 3. 格式升级：v1 → v2

### 3.1 结构变更

`ipdb.Record` 与 `ipdb.Location` 各加一个 `ISP string`；`locationSize` 6 → 8（多一个 uint16 字符串池下标）；`formatVersion` 1 → 2。字符串池、段区、头部布局都不变，ISP 与 Country/Region/City 走同一套 intern。

### 3.2 `Parse` 必须同时认 v1 和 v2

读到 v1 时按 6 字节读归属地表、ISP 留空；读到 v2 时按 8 字节读。`Build` / `BuildRecords` 只产 v2。

这一条不是兼容性洁癖，是升级路径的必需品。面板升级后，机器上 `/etc/<name>/ipdb.dat` 与 `qqwry.dat` 仍是 v1；`Parse` 若直接拒绝，两个库一起加载失败，**整个归属地列当场消失**——不只是新的运营商列为空，连现在能用的「中国 山东省 聊城市」也没了，共享检测的省份判定同时失效。而界面上只会显示「未加载」，没有任何东西说明是格式版本的问题，管理员会以为是下载出了错。恢复要等到次日的定时更新时刻。

### 3.3 本地库还是 v1 时不带条件请求头

`IPDBService.fetchAndBuild` 目前的条件请求逻辑是：

```go
if src.EtagKey != "" && s.dbOf(src.Key) != nil {
    // 带上 If-None-Match
}
```

升级后本地 v1 库能被 §3.2 的兼容 `Parse` 正常加载，于是 `dbOf(...) != nil` 成立、带上 ETag、上游源文件没变、服务端返回 **304**、`errIPDBNotModified`、库不重建。**结果是运营商列永远是空的**，管理员点「更新」按钮也只会得到「已是最新」。这是一个完全静默、且不会自愈到可预期时间的失效。

因此把条件头的判据从「本地那份确实在用」收紧成「本地那份确实在用**且已经是当前格式**」：`DB` 暴露 `HasISP() bool`（内部按解析出来的格式版本置位），`fetchAndBuild` 在它为 false 时不带条件头，强制全量下载重建一次。

选它而不是「升级时清一次 ETag」：后者要写一段一次性迁移代码，且只覆盖这一次升级；前者是自愈的——任何原因让库退回 v1（回退过一次二进制、手工拷了旧文件），下一次更新都会自动把它重建成 v2。

### 3.4 回退到旧二进制

旧 `Parse` 认不了 v2，会报「格式版本为 2，本程序只支持 1」，两个库都加载失败，归属地不可用。下一次定时更新会用旧代码的 `Build` 把库重建成 v1，自愈。

不为此做兼容（比如同时写两份文件）：回退是低频操作，且这个失效是**可自愈且有明确报错**的（日志里能看到版本号不匹配），与 §3.2 那个「升级后静默消失」的性质完全不同。

### 3.5 种子库

`bin/ipdb.dat` 是仓库跟踪的（`util/ipdb/realdata_test.go` 直接对它断言），格式升级后必须重新生成并提交。体积从 2.18 MB 变为 2.25 MB（实测，非估算）。

## 4. ISP 归一化（新增 `util/ipdb/isp_name.go`）

与现有的 `province_name.go` / `CanonicalProvince` 同构：一个纯函数，两个源的解析器都调它，落库的是归一后的值。

**归一必须发生在落库前，不能放到展示层。** 两个理由：一是格式的归属地种类上限是 65536，不归一直接撞上限（见 §4.1）；二是展示层归一意味着两个源各存各的写法，而 `Multi.Lookup` 的分歧判定是按字符串相等做的，ip2region 的「中国电信」与纯真库的「电信」会被判成分歧，「存疑」标签对几乎每个 IP 亮起，把这个本来有用的提示废掉。

### 4.1 第一步：清洗

去首尾空白；`CZ88.NET`（纯真库的广告占位，3315 条）归空；取 `/` 前的部分（纯真库大量的「电信/新世纪网吧」「移动/全省通用」这类细分）。

单这一步就把纯真库中国段的 ISP 取值从 **115,619 种压到 4,013 种**。不做的话，归属地种类会远超格式的 65536 上限，`BuildRecords` 报「归属地种类超过 65536」，整次更新失败并保留旧库——按现有设计这是正确的失败方式，但功能永远上不了线。

### 4.2 第二步：归一到同一套名字

映射表（两个源共用）：

| 归一结果 | 来源写法 |
|---|---|
| 中国电信 | 电信、中国电信、China Telecom、CHINANET |
| 中国联通 | 联通、中国联通、网通、中国网通、China Unicom |
| 中国移动 | 移动、中国移动、铁通、中移铁通、China Mobile |
| 中国广电 | 广电网、中国广电、广电 |
| 教育网 | 教育网、中国教育网、CERNET |
| 腾讯云 / 阿里云 / 华为云 | 腾讯、腾讯云、阿里、阿里云、华为、华为云 |
| Google / Amazon / Microsoft | Google LLC、谷歌、Amazon、AWS、Microsoft、微软 |

ip2region 自身口径就不统一（「电信」17,135 条与「中国电信」1,212 条并存，「联通」11,901 与「中国联通」172 并存），所以这张表对单个源也是必要的。

认不出的取值**原样保留**（管理员选择的口径）：「鹏博士宽带」「华数宽带」这类地方运营商本身就是有效信息，映射表不可能穷举。

### 4.3 第三步：境外只保留知名 IDC / 云厂商

境外段的 ISP 只在命中云厂商关键词（amazon/aws、google、cloudflare、microsoft/azure、oracle、digitalocean、linode、vultr、ovh、hetzner、akamai、fastly、alibaba、tencent、huawei 等）时保留，其余留空。

这一条不是可选优化。三种口径的实测（对两个源的真实全量源文件跑的）：

| 口径 | 纯真库段数 | 纯真库体积 | ip2region 段数 | ip2region 体积 |
|---|---|---|---|---|
| 现状（无 ISP） | 261,670 | 2.62 MB | 216,446 | 2.17 MB |
| **中国全量 + 境外仅 IDC** | 270,627（+3.4%） | 2.78 MB | 220,072（+1.7%） | 2.25 MB |
| 全部带 ISP | 858,363（**+228%**） | 8.74 MB | 244,840（+13%） | 2.54 MB |

归属地种类数：现状 927 / 650，推荐口径 8,748 / 4,750，全部带 ISP 19,903 / 11,445。三种口径都低于 65536 上限，所以上限不是这里的约束——**约束是段数**。

表中 ip2region 那两列是实现后拿真实源文件跑出来的实测值；纯真库那两列仍是测算值（用同一套清洗与关键词规则模拟合并），实际会比测算略低，原因与 ip2region 相同：`CanonicalISP` 的归一比测算脚本更彻底，相同 key 更多、合并得更多。

纯真库对境外 IP 的 ISP 字段极其细碎，全量保留会让相邻段合并几乎完全失效，段数涨到 3.3 倍，文件与常驻内存跟着涨（`segments` 是常驻切片）。而「境外只认云厂商」保住了识别机房这个全部价值——境外来源 IP 本来就只显示国家，能显示成「United States · Amazon」已经是全部所需——只付 1/40 的代价。

## 5. 不受影响的三处（已核实）

- **地区限制的 geo dat 生成**：`DB.CIDRsOfProvinces` 按 `Region` 过滤后**自己重新合并连续区间**（`hasRange && end+1 == s.start`），不依赖 `segments` 的合并粒度。同城不同 ISP 拆成的两段仍然连续，会被重新合并成同一个区间，输出的 CIDR 集合**逐字节不变**。这一点必须有测试钉住：输出变化会改变 geo dat 的内容哈希，进而让那个 10 秒的重启 cron 反复重启 xray。
- **共享检测**：`SharingService.provinceOf` 只读 `sl.Location.Region`。
- **省份下拉框**：`DB.Provinces` 按 `Region` 去重，仍是 34 个；只是遍历的 `locations` 从 650 变 4,750。

设置页「IP 归属地库」那一栏显示的段数会变（216,446 → 221,999，261,666 → 270,627），这是预期内的可见变化。`minValidSegments` 是下限，段数增加不会触发它。

## 6. 服务层与展示层

### 6.1 服务层

`OnlineIP` 加 `ISP` / `ISPAlt` 两个字段，与现有的 `Location` / `LocationAlt` 同构。判定逻辑收敛在 `locateWithIPDB` 一处——在线明细与访问日志共用它，代码里现有的注释明写了「避免两处结论对不上」。

签名从 `(primary, alt string)` 扩成一个小结构体，避免四个同类型返回值的调用点极易写反。

### 6.2 分歧显示：复用现有的「存疑」标签

归属地或运营商任一不一致就亮「存疑」，tooltip 里分行说明分歧在哪一项。不给运营商单开一个标签：展开行的标签已经不少（超额被拒 / 闲置 / 已封禁 / 存疑），再加一个会让这一行更难扫读，而管理员真正要的信息是「这一行的判定有分歧，别全信」，具体分歧在哪展开 tooltip 看即可。

这与现有「不做仲裁，把分歧原样显示」的取向一致。

### 6.3 前端

- `web/html/xui/inbounds.html`：`onlineColumns` 在「归属地」后插一列「运营商」，宽度 110。机房标识（命中云厂商映射的值）用与运营商不同的标签颜色，让「这个来源是机房」在扫读时能立刻看出来。
- `web/html/xui/access_log_modal.html`：来源 IP 列表与日志表格两处同步显示。

两个页面的表格总宽会增加，需要实机确认展开行不出现横向滚动条。

## 7. 已知取舍

- **归一化表要手工维护。** 上游出现新的写法（比如某天 ip2region 把「电信」全量改成「中国电信」）时，映射表不更新只会让新写法原样显示，不会报错。可接受：原样显示的是一个真实的运营商名，不是错误信息。
- **境外 IDC 关键词表同理，且漏掉的后果是「境外某机房 IP 的运营商列为空」**，与现状（一律为空）一致，不构成退化。
- **本次不修那个假「存疑」。** 用户当前看到的存疑（`123.171.5.200`）实际来自城市名后缀差异：ip2region 说「聊城市」、纯真库说「聊城」，两个源的 ISP 反而完全一致（都是「电信」）。归一化城市名是另一件事，会改变归属地字符串本身，影响面比本次大，另开一期。
- **ISP 不进历史、不进访问日志的持久化表。** 它是 IP 的属性、随库更新而变，存快照只会让老数据显示一个与当前库不一致的值。查询时实时判定。

## 8. 测试

- `util/ipdb`：v1 文件能被新 `Parse` 读出（ISP 为空）、v2 往返一致、`HasISP()` 对两种版本的返回值。
- `util/ipdb/isp_name_test.go`：清洗（`CZ88.NET`、`/` 截断）、映射（两个源的不同写法收敛到同一结果）、境外过滤（命中云厂商保留、其余留空）。
- `util/ipdb/realdata_test.go`：对重新生成的 `bin/ipdb.dat` 断言 `123.171.5.200 → 中国/山东省/聊城市/中国电信`、`8.8.8.8 → United States / Google`（源数据是 `United States|California|0|Google LLC|US`，境外省市按既有规则丢弃，ISP 命中关键词后归一为 `Google`）。
- **`CIDRsOfProvinces` 的输出在加 ISP 前后逐字节相同**——用同一份源数据分别按 v1、v2 口径构建，比对某几个省的 CIDR 列表。这条守的是 §5 那个「geo dat 不变」的结论。
- `util/qqwry`：`toRecord` 产出的 ISP 经过归一。
- `web/service`：`locateWithIPDB` 在两个源 ISP 不一致时把分歧带出来。
- `web/html_test.go` 的既有模板测试对新列自动生效。

## 9. 发布

格式升级 + 种子库重新生成 + 前端两处，同一个版本发布。升级后的第一次 IP 库更新会因 §3.3 强制全量下载（约 35 MB + 25 MB），之后恢复条件请求。这一次多出来的下载要写进发布说明。
