# 地区限制：失败收窄、预演、出差通行证与自动出差放行

状态：设计已获管理员认可（2026-11-09 会话），实施中。

## 1. 为什么做

地区限制按「人在哪」准入，管理员的真实目标是防共享。前一轮只读分析（四个候选方案经对照代码的压力测试与对抗核验）的结论：

- 地区限制是唯一不依赖 SOCK_DESTROY、能拦跨省（含错峰）共享的现成手段，但它不灵活：不知道该填哪些省、出差被挡、被挡的人看到「能连上但没网」。
- 客户出差时**不会主动找管理员**，所以放行必须自动化。
- 地区限制的生成链有两处现存缺陷，会把一个入站的问题放大成整机故障。

本设计只覆盖分析中的「阶段 1」「阶段 2」以及一处顺带发现。每设备独立凭证（阶段 3+）与「不建议做」清单里的一切不在范围内。

## 2. 目标 / 非目标 / 反目标

目标：

1. 一个入站的地区规则出问题，只影响这一个入站，其余下发照常。
2. IP 归属地库更新后，新的允许集能进核心。
3. 保存时拦住非法省名。
4. 设置地区前能预演「会拦掉谁」。
5. 出差通行证：手动发放 + 按入站开启的自动出差放行。
6. 被拦记录标注「疑似共享 / 疑似出差」。
7. 修掉「超额被拒」标记不过期。

非目标：每设备凭证；按省计数的并发；常用网络白名单；改变 ConcurrencyLimit 口径；IPv6 监听行为（只有源码推断，没有 Linux 实测，本次不改 `model.go` 的 listen 逻辑）。

反目标（做出来就算失败）：

- 自动放行变成 TOFU：根据观测自动**收紧**或自动封禁。本设计的自动化只**临时放宽**，并且永远可以撤销、有到期时间。
- 一次瞬时故障把付费客户整个锁死，界面上却毫无提示。
- 通行证被编辑表单静默清零或复活。

## 3. 阶段 1：失败收窄

### 3.1 地区规则生成不再让整份配置失败

现状：`buildGeoRules` 任一步失败 → `GetXrayConfig` 失败 → 10 秒 cron 已消费掉重启标志，到期停用、超额停用、增删入站都进不了核心；冷启动时所有入站都起不来。

新语义，按**入站**收窄：

| 情况 | 处理 |
|---|---|
| 入站地区 JSON 损坏 | 该入站 fail closed |
| IP 库未加载 | 每个配了地区的入站：沿用上次成功的允许集（last-known-good），没有则 fail closed |
| 某个 tag 算出空集 | 同上 |
| 写 dat 失败 | 读回现有 dat：其中已有的 tag 照用（ruleTag 用现有文件的哈希），缺的入站 fail closed；连现有 dat 都读不出时，所有地区入站 fail closed |

- **last-known-good**：进程内 `tag → CIDRs` 缓存，每次成功生成后更新；冷启动时从现有 `bin/a-ui-geo.dat` 解码出来做种子（`util/geodat` 新增 `Decode`）。
- **fail closed**：为该入站生成一条 `source: ["0.0.0.0/0", "::/0"] → a-ui-block` 的规则，不引用 dat。只锁这一个客户。
- **降级状态必须可见**：包级状态 `geoDegraded map[inboundId]{Mode: "stale"|"closed", Reason}` 在每次生成时整体替换。「需要留意」摘要下发这个状态，入站行显示红色提示。日志按「状态变化」去重，不每 10 秒刷一遍。
- 现有测试 `geo_test.go` 中「整份失败」的断言改写为新语义（管理员已在本次会话授权这项设计变更）。

### 3.2 IP 库更新后触发下发

`IPDBUpdateJob.Run` / `RunInitial` 与 `SettingController.updateIPDB` 在 `updated > 0` 时调用 `XrayService.SetToNeedRestart()`。`Config.Equals` 会把「其实没变」过滤掉，所以无需额外判断有没有入站在用地区。

### 3.3 保存时校验省名

`InboundService` 写入路径（Add / Update）：只有提交的地区集合与库里旧值**不同**时才校验（不阻断与地区无关的编辑）：

- IP 库已加载：每个省名必须在 `db.Provinces()` 里；按当前合并口径算出的允许集不能为空。
- IP 库未加载：拒绝新设或修改地区，提示先更新 IP 库。

### 3.4 顺带：「超额被拒」标记过期

`Enforce` 每轮结束后，清掉本轮未被判定的端口的 `rejectedNow`（包括没有任何受限入站、提前返回的那一轮）。新增 `onlineTracker.retainRejectedPorts(ports)`。

## 4. 阶段 2：灵活的地区限制

### 4.1 有效地区 = 存储的地区 ∪ 活动通行证

新表（主库）`InboundRegionPass`：

```
Id, InboundId(index), Regions(JSON 省名数组；"*" 单元素表示「暂停地区限制」),
Auto(bool), GrantedAt, Until(ms), EndedAt(ms, 0=活动), EndReason(string)
```

- 每个入站最多一张活动通行证；发新的时候，旧的以 `replaced` 结束。
- 生成期（`buildGeoPlan`、`newGeoBlockMatcher`）读活动通行证，**不读时间**：「活动」= `EndedAt == 0`。到期完全由任务负责。
- `effectiveRegions(in, pass)`：没有通行证时就是 `Regions`；`*` 表示不生成地区规则；否则取并集。`model.go` 的 listen 逻辑只看存储的 `Regions`，保持不变。
- 通行证不在 `model.Inbound` 上，编辑表单碰不到它，也就不存在被清零或复活的问题。
- `DelInbound` 在事务里连带删除通行证（失败即阻断，与 IPBan 同理：SQLite 会复用 id）。

到期：`CheckInboundJob` 调 `RegionPassService.ExpireDue(now)`（`UPDATE … SET ended_at=now, end_reason='expired' WHERE ended_at=0 AND until<=now`），`RowsAffected > 0` 时置重启标志。清理失败时通行证会一直生效，失败方向是放宽，所以记 Warning。

手动接口：
- `POST /aui/inbound/regions/pass/grant/:id`：`regions`（JSON 数组，或 `["*"]`），`hours`（1–720）；
- `POST /aui/inbound/regions/pass/revoke/:id`；
- `POST /aui/inbound/regions/pass/list/:id`：最近 30 条记录。

授予和撤销之后都置重启标志，只改路由，走热应用。

### 4.2 预演

`POST /aui/inbound/regions/preview`：`id`、`regions`（JSON 数组）。

- 取该入站近 7 天的 `InboundIPHour` 行，用**与执行同口径**的 CIDR（`regionCIDRSource(db).CIDRsOfProvinces`）建一个内存 CIDR 集合，逐 IP 判断。不用行里的 Province 列：那是按源顺序取的快照，与执行口径不同。
- 输出：
  - 总活跃小时 / 字节；
  - 会被拦的来源（IP、快照归属地、小时数、字节、最后活跃时刻），按字节降序，最多 20 个；
  - IPv6 来源单列为「启用后不可用」；
  - 被拦字节占比；
  - 同一份数据的地区建议（`suggestRegions`）。
- IP 库未加载或省名非法时返回明确错误。

### 4.3 被拦记录标注

「需要留意」里每个被地区拦下的 IP，额外下发：

- `Province`：多数票显示省，供一键发通行证；
- `Kind`：
  - `coexist`（疑似共享）：最后一次被拦的那个小时或前一小时里，存储允许集内的来源有实质流量（`InboundIPHour.ActiveBytes ≥ 1MB`）；
  - `travel`（疑似出差）：同一时段允许集内没有实质流量。

只做标注，不自动放行。自动放行由 4.4 单独负责，规则更严。

### 4.4 自动出差放行（按入站开启）

`model.Inbound` 新增 `AutoTravel bool`（表单可改，走 `UpdateInbound` 白名单、models.js、两处提交体）。只对「启用 + 配了地区 + 开了自动出差」的入站生效。

任务 `AutoTravelJob`，每分钟一次。参数先用常量（会话中尚未确认具体取值，先取下表默认值，以后可做成设置项）：

| 常量 | 默认 |
|---|---|
| 家里静默时长 | 2 小时（当前小时与前两小时内，允许集内没有 ≥1MB 的小时行，在线表里也没有活跃的允许集来源） |
| 「有稳定的家」 | 近 7 天中至少 3 个不同的日子，允许集内有实质流量 |
| 被拦来源回看 | 10 分钟访问日志 |
| 单次通行证 | 72 小时 |
| 续期 | 剩余不足 24 小时，家里仍静默，且通行证省份内 24 小时内有实质流量 → 续到 now+72h |
| 每月自动放行天数上限 | 10 天（按面板时区的自然月，按通行证实际生效时长累计） |
| 一周内自动发放次数上限 | 3 次 |
| 并存后冷却 | 7 天内不再自动发放 |

发放流程（对每个合格入站）：
1. 需要访问日志开启，否则记录状态「访问日志未开启，无法自动放行」。
2. 近 10 分钟访问日志里该入站进了 `a-ui-block`、且被地区规则拦下的来源。访问日志里有路由结果，说明已经过了协议鉴权，扫描器不会出现在这里。
3. 若已有活动通行证（手动或自动）→ 不重复发放。
4. 风险引擎快照 `Level` 为 `high` / `severe` → 拒绝。
5. 有稳定的家、家里静默、未在冷却期、未超月度天数、未超周次数 → 对来源 IP 取候选省份，用与执行同口径的 CIDR 集合验证该 IP 确实落在这个省里，然后授予 `[省]`、72 小时、`Auto=true`。IPv6 与境外来源不发放。
6. 置重启标志。

结束流程（活动的自动通行证）：
- 家里恢复实质流量：
  - 在线表里此刻同时有活跃的允许集来源和通行证省份来源 → `EndReason=coexist`，进入冷却期；
  - 否则 → `EndReason=home`。
- 剩余不足 24 小时 → 按上表续期。
- 到期由 4.1 的 `ExpireDue` 负责。

每个入站最近一次的判定结果（发放、拒绝及原因、结束及原因）存在内存里，「需要留意」下发；发放和结束记录在通行证表里，可追溯。

## 5. 界面

不新增页面，沿用入站列表、入站编辑表单与现有组件：

- 入站编辑表单 · 地区限制区域：「预演」按钮（结果在表单内展开）、「填入建议」、自动出差开关（只有配了地区才可用）。
- 入站行 chip：活动通行证（手动 / 自动、到期时刻）；地区规则降级（红色）。
- 「需要留意」里的地区拦截：每个 IP 显示省份与「疑似共享 / 疑似出差」标签；「疑似出差」带「发通行证」按钮。
- 通行证弹窗：发放（省份多选或「暂停地区限制」，时长）、撤销、最近记录。

UI 实施时必须加载 ui-ux-pro-max，并在本地实际渲染验收。

## 6. 前提与已知局限

- 客户端直连，没有 CDN 或中转（所有按源 IP 的判断都依赖这一点）。
- 自动放行依赖访问日志、按来源 IP 的小时用量和在线表，只对可观测传输（tcp/ws/grpc/h2）有效。
- 自动放行与错峰共享在数据上同形，只靠频率上限、冷却期和风险等级来压制，无法根除。
- 被拦到放行之间约 1 分钟加 10 秒的下发延迟；家里一直跑流量的客户永远满足不了「家里静默」。
- IPv6 来源与境外来源不会被自动放行。
