# 自动设置地区限制

状态：设计已获管理员认可（2026-11-09 会话），实施中。前置：`2026-11-09-region-flexibility-auto-travel-design.md`（通行证与自动出差放行）。

## 1. 为什么做

管理员希望没有设置地区限制的用户——新加的和存量的——都能自动得到地区限制，而不必记着一个个去设。

「首次连接即锁定」（TOFU）当初被否决，理由有四条：第一个连上来的可能不是本人；手机出口会漂移、人会出差；IPv6 用户会被挡；被挡的人无法自救。这次不看第一次连接，看一段时间的数据，并且只在条件全部满足时才动手。出差由已有的自动出差放行兜底。IPv6 不考虑：管理员确认生产不使用 IPv6。

## 2. 目标 / 非目标 / 反目标

目标：
- 观察期满、条件全部满足时，自动写入建议的省份，并同时打开自动出差放行。
- 条件不满足时不动，把原因与建议摆到「需要留意」，由管理员一键确认或忽略。
- 每一次自动设置都能看见、能一键撤销。

非目标：同省共享（地区手段管不到）；对已经设了地区的入站做任何收紧或放宽。

反目标：
- 覆盖管理员的决定。凡是管理员动过地区（设置、清空、撤销、忽略），这个入站以后不再自动设置。
- 把并存省份「合法化」进允许集。有并存嫌疑就只提建议，不自动写。

## 3. 开关与参数（面板设置 → 连接限制 → 自动设置地区限制）

| key | 默认 | 范围 | 含义 |
|---|---|---|---|
| `autoRegionEnable` | 0 | 0/1 | 总开关。默认关：升级后行为零变化，由管理员打开 |
| `autoRegionObserveDays` | 1 | 1 ~ 30 | 最早一条用量记录距今至少这么多天才判定（管理员要求默认 1 天） |
| `autoRegionMaxBlockedPercent` | 5 | 0 ~ 50 | 按建议设置后，近 7 天会被拦的流量占比上限 |

「稳定使用天数」沿用自动出差放行的 `autoTravelStableDays`（近 7 天至少几天有实质流量），但这里取它与观察天数中较小的一个：观察期设为 1 天时只要求 1 天的数据。

## 4. 状态（表 `inbound_auto_regions`，主库，每入站一行）

```
InboundId(pk), State, Regions(JSON), Reason, UpdatedAt(ms)
```

State 的取值：
- `pending`：条件不满足，等待管理员确认。
- `applied`：已自动设置。
- `manual`：管理员接手了。以下任一情况都会进入这个状态：
  - 确认了建议；
  - 忽略了建议；
  - 撤销了自动设置；
  - 在编辑表单里改过地区。

  进入后永不再自动设置。

没有行，表示还在观察或从未判定。删除入站时在 `DelInbound` 的事务里连带删除。

## 5. 判定（AutoRegionJob，每 10 分钟）

总开关打开时，判定范围是同时满足以下条件的入站：
- 启用；
- 存储的 Regions 为空；
- 状态不是 `manual` / `applied`。

`pending` 每轮都会重算，条件变好时自动转成 `applied`。

判定前提：
1. IP 库已加载。
2. 最早的用量记录距今 ≥ 观察天数，且近 7 天有实质流量的天数 ≥ 稳定使用天数。不满足就继续观察，不写状态。
3. 近 7 天按 IP 的小时行算出地区建议（`suggestRegions`）。建议为空就继续观察。

满足前提后，依次检查，第一条不满足的作为 `pending` 的原因：
- 建议里有省份出现在并存记录中：「有异地同时使用，建议含 X，请确认」；
- 共享风险等级 ≥ medium：「共享风险偏高，请确认」；
- 按建议预演，被拦流量占比 > 上限：「设置后近 7 天会拦掉 N% 的流量，请确认」。

全部通过时：
- 写 Regions = 建议，AutoTravel = true；
- 状态记为 `applied`；
- 置重启标志。

写入走 `UpdateColumns`，不经编辑表单路径，但同样先过 `checkRegionsUsable`。

## 6. 管理员操作（接口）

- `POST /aui/inbound/autoRegion/confirm/:id`：按 pending 的建议写入（Regions + AutoTravel），状态记为 `manual`。
- `POST /aui/inbound/autoRegion/dismiss/:id`：状态记为 `manual`，什么都不写。
- `POST /aui/inbound/autoRegion/undo/:id`：只对 `applied` 有效。清空 Regions，关闭 AutoTravel，结束活动通行证，状态记为 `manual`。
- `UpdateInbound` 里地区被改动时，状态记为 `manual`。

这些操作都置重启标志（dismiss 除外）。

## 7. 可见性

「需要留意」下发 `autoRegion`：
- `pending`：附建议与原因；
- `applied`：只在 7 天内下发，附设置时刻与省份。

入站列表：
- `pending`：显示「建议地区 · 江苏省」按钮，点开弹窗，里面有原因、确认、忽略；
- `applied`（7 天内）：显示「自动设置」标签，点开弹窗可撤销。

侧栏提醒点计入 `pending`。

## 8. 已知局限

- 设置地区会让该入站从留空监听变成 `0.0.0.0`，热应用时这个入站会先删后加，在线连接短暂断开。
- 从第一天起就固定两省同用的，系统分不清谁是本人，会落到 `pending`。
- 只在面板上显示，没有推送。
