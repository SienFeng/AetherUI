# 入站管控（并发 / 地区 / 限速 / 在线明细 / 续期）总体设计

日期：2026-09-02
状态：待评审

本文档是「入站管控」这一组功能的**总纲**：确定分层、不变量与子项目拆分。每个子项目在动工前另写自己的详细设计文档，并以本文档为约束来源。

本文档不修订既有的三份分流设计文档。分流子系统的四条不变量——「一律 append 到末尾」「block 规则排在 proxy 之前」「生成逐字节确定」「绝不输出条件残缺的规则」——继续全部有效，本文档只在 §4.2 对**第一条**做一处受控的例外并说明理由。

## 1. 背景与目标

面板目前对一个入站（= 一个用户）只能管三件事：总流量、到期时间、启用与否。管理员实际需要的是：

1. **并发限制**：一个入站同时只允许 N 个不同来源 IP 使用，超出的连不通。
2. **地区限制**：只允许指定省份的 IP 使用该入站，其余一律拒绝。
3. **限速**：限制单个入站的上行 / 下行带宽。
4. **在线明细与访问日志**：谁在用、从哪来、实时网速多少、访问了什么、走了哪条路由；能手动踢人。
5. **一键续期**：按 7/30/60/90/180/365 天或自定义日期续期。

### 非目标

- 不做「一个入站多个用户」。前端每个协议表单只绑定 `settings.<protocol>es[0]`，一个入站恰好一个用户，本组功能全部按入站维度建模。
- 不做客户端设备识别。见 §2.3。
- 不引入面板流量中转层。见 §3.1 被否决方案。

## 2. 已验证的事实

以下均由仓库内的 Xray 26.7.28（`bin/xray-darwin-arm64`）实测确认，不是推断。**它们是本设计全部决策的地基，改动相关代码前先复核。**

### 2.1 xray 能做什么

| 能力 | 验证方式 | 结论 |
|---|---|---|
| 运行时增删路由规则 | `xray api adrules` 的用法串 | 吃**标准 routing JSON**，`rmrules` 按 **`ruleTag`** 精确删除，**免重启生效** |
| 在线用户 / 在线 IP | `api statsonline` / `statsonlineiplist` / `statsgetallonlineusers` 存在；debug 日志可见 `create new OnlineMap user>>>u1@a-ui>>>online` | 存在，但见 §2.4 |
| 用户级流量统计 | 实测 `statsquery -pattern "user>>>"` 返回 `user>>>u1@a-ui>>>traffic>>>uplink` | 可用（需 client 带 `email` + 开 `statsUserUplink/Downlink`） |
| 访问日志 | 实测跑通 | 格式见 §2.2 |
| 路由 `source` 条件 | `run -test` + 实跑对照 | 接受裸 CIDR（含 `::/0`）、`geoip:xx`、`ext:<file>:<tag>`；`ruleTag` 在**静态配置**里同样合法 |
| **`!` 取反语法** | 四组可区分对照实跑 | `ext:f.dat:!TAG` 与 `geoip:!tag` **都生效**；tag 匹配**大小写不敏感** |
| dat 内的 `reverse_match` 字段 | 手写 dat 实跑对照 | **不被采纳**。配置层只取 `cidr` 列表，取反只能写在配置字符串里 |
| 纯 IPv4 允许集 + `!` 遇到 IPv6 来源 | `::1` 来源实跑 | **fail open**，IPv6 被放行。必须另加 `source:["::/0"]` 规则才能 fail closed（已验证有效） |

### 2.2 访问日志的确切格式

```
2026/09/02 22:11:53.537856 from tcp:127.0.0.1:55937 accepted tcp:example.com:80 [inbound-39002 -> direct]
2026/09/02 22:43:15.584934 from 127.0.0.1:60766 accepted tcp:www.bing.com:443 [inbound-39010 >> direct] email: u1@a-ui
```

三处必须写进解析器的细节：

- 来源地址前缀 **`tcp:` 时有时无**（两行实测输出不同），解析器必须两种都认。
- 入站与出站之间的分隔符有 **`->` 和 `>>` 两种**，都要认。
- 客户端配了 `email` 时行尾追加 ` email: xxx`，没配则没有这一段。

### 2.3 xray 拿不到的东西

- **客户端设备 / 操作系统 / 客户端软件**：没有 UA，没有设备标识；TLS 由 xray 终结且不向外暴露指纹。图 #2 里的「客户端设备」一列因此**去掉**，不做任何猜测式实现。
- **任何形式的限速或连接数上限**：`policy.levels` 的全部字段只有 `handshake` / `connIdle` / `uplinkOnly` / `downlinkOnly` / `bufferSize` / `statsUserUplink` / `statsUserDownlink` / `statsUserOnline`（从二进制的 json tag 枚举确认）。限速与并发强制**必须由面板自己实现**。
- **省份粒度的 IP 归属**：`geoip.dat` 只到国家级。

### 2.4 尚未验证、必须在生产机上确认的点

`statsonlineiplist -all -include-traffic` 在开发机（macOS）上**始终返回 `{}`**：来源是回环地址时在线表已创建但无条目；改用局域网地址后连接被本机防火墙/VPN 拦截、根本没到达服务端，无法构造出有效样本。

因此**「这个 API 能否直接给出每个 IP 及其流量」目前未知**。本设计不依赖它——在线明细与并发计数改用内核连接表（§3.2）。它保留为后续的交叉校验手段，验证工作放在 Linux 生产机上做。

### 2.4.1 子项目 3 引入的内核侧约束

以下是实现在线明细时确定的事实，子项目 4（并发限制）直接依赖它们。

| 事项 | 结论 |
|---|---|
| 数据来源 | `NETLINK_INET_DIAG` + `SOCK_DIAG_BY_FAMILY`，请求 `INET_DIAG_INFO` 扩展 |
| 依赖 | 全部用 Go 标准库 `syscall`，**零新依赖**（`SOCK_DIAG_BY_FAMILY`=20 / `SOCK_DESTROY`=21 不在标准库里，自行定义） |
| 字节计数 | `tcp_info` 的 `tcpi_bytes_acked`（偏移 120）= 下行、`tcpi_bytes_received`（偏移 128）= 上行，Linux 4.1 起存在；属性长度不足时必须降级为「字节数不可用」而不是硬读 |
| 踢人 | `SOCK_DESTROY` 需要 `CAP_NET_ADMIN` 且内核开 `CONFIG_INET_DIAG_DESTROY`；请求必须带 `NLM_F_ACK`，否则成功与「内核不支持」无法区分 |
| **UDP 类传输不可观测** | mKCP / QUIC 在端口上只有一个 socket，xray 自己做复用，内核连接表里没有每个客户端的条目。这类入站的在线明细**只能如实标注不可用**，并发限制同样无法按此方案实施 |
| 端口归属 | 按 socket 的本地端口匹配入站。理论上出站连接的临时源端口可能撞上入站端口，但内核不会把已被 listen 绑定的端口分配为临时端口，实践中不会发生 |
| 上线时间 | 内核不提供 socket 建立时间，展示的是**面板首次观测到该 IP 的时间** |

### 2.4.2 子项目 5 复核的日志格式

在仓库内的 Xray 26.7.28 上重新实测，§2.2 记录的三条细节全部成立，并补充一条：

- 分隔符的两种形态**同时出现在同一次运行里**：命中路由规则的连接输出 `->`，走默认出站的输出 `>>`。
- 还存在**三段形态** `入站 -> 中间出站 -> 最终出站`。解析器取第一段为入站、其余整串为路由，不能只取最后一段，否则「经过了谁」这个信息会丢。
- 入站握手失败（例如往 socks 端口发垃圾）**不写访问日志**，只进错误日志。因此实际内容里 `accepted` 占绝对多数。

这些结论有一条跑真实 xray 的端到端测试守着（`web/service/accesslog_e2e_test.go`）：起一个 socks 入站、连一个本地监听、读回日志文件、过一遍解析器再入库。它不依赖外网，没有 xray 二进制时自动跳过。

### 2.4.3 子项目 6a 复核的地区限制机制

§4.2 与 §4.3 的全部关键假设都用仓库内的 Xray 26.7.28 重新实测过，并有一条端到端测试守着（`web/service/geo_e2e_test.go`）：

| 假设 | 实测结论 |
|---|---|
| 手写的 protobuf 编码 xray 能读懂 | 成立。`util/geodat` 约 100 行，零依赖 |
| `ext:<文件>:!<TAG>` 取反生效 | 成立。允许集含来源 IP 时放行、不含时进黑洞，访问日志显示 `[in -> a-ui-block]` |
| dat 文件的查找位置 | **xray 二进制所在目录**。文件放 `bin/a-ui-geo.dat`，配置里写 `ext:a-ui-geo.dat:!TAG`，**不带目录前缀** |
| 「Configuration OK」不等于生效 | 再次印证：情形 A/B 的配置都 OK，只有实跑才能分辨 |

补充两条实现约束：

- **允许集为空必须报错**，不能生成规则。空集合会让「来源不在集合里」匹配到所有人，该入站被彻底封死。查不到省份 IP 段（库未加载、省份名变更）时让整份配置生成失败，xray 保持原状。
- **IP 库未加载时绝不省掉地区规则**。省掉等于限制失效而面板显示一切正常，是本组功能里最危险的静默失效形态。

### 2.4.4 纯真 IP 库的格式细节（实测）

拿真实的 25 MB `qqwry.dat` 验证，149 万条记录全部解析成功，**零乱序、零重叠**（直接满足 `ipdb.BuildRecords` 的前提，不需要额外清洗）。中国段 36.3 万条，其中 99% 能定到省，34 个省级地区全覆盖。

四个必须处理的细节，前三个我在写快速原型时都踩过：

- **GBK 编码**，不是 UTF-8。
- **`0x01` / `0x02` 重定向**要递归跟进。`0x01` 是整条记录重定向、`0x02` 只重定向国家字符串。不处理会解出乱码。注意 `0x01` 分支单看国家是「碰巧对」的——字符串读取自己也会跟重定向——只有看地区（ISP）字段才能分辨，所以那条测试直接测内部的 `resolve`。
- **分隔符是 `–`（U+2013 EN DASH）**，不是普通连字符也不是 `|`。
- **省份名是短名**（`江苏`、`北京`），而 ip2region 用的是全名（`江苏省`、`北京市`）。两者必须归一到同一套写法（`ipdb.CanonicalProvince`），否则同一个省会因为写法不同被当成两个地区，多源合并直接失效。而且**不是每条都有省份**：云厂商 anycast 段可能只有「腾讯云」或「中国」，认不出省份时必须留空，**绝不能硬塞**——把「腾讯云」当成省份会污染整个允许集。

### 2.5 一处环境陷阱（排查时会踩）

开发机存在 **fake-IP DNS**（`example.com` 被解析为 `198.18.1.42`），xray 的 freedom 出站会把这类保留段目标直接黑洞掉并打印 `blocked target: ..., blackholing connection`。在本机测试代理链路时**必须用真实公网 IP 直连目标**，否则会误判成 xray 或配置有问题。

## 3. 分层

四组功能落在三层，这决定了代码归属：

```
                    ┌─ 观测层（内核）────────────────────────┐
客户端 ──TCP──▶ 内核 │ netlink INET_DIAG：连接表(源IP/字节数)  │──▶ 在线会话 / 每IP实时网速 / 踢人
                    └────────────────────────────────────────┘
                 ▲  ┌─ 执行层（内核）────────────────────────┐
                 └──│ tc HTB + ifb：按入站端口限上/下行       │
                    └────────────────────────────────────────┘
              ┌─ 执行层（xray）────────────────────────────────┐
              │ 路由规则（带 ruleTag）：地区拒绝 / 并发超额封禁  │
              │ access.log：时间·源IP·域名·入站·出站            │
              └────────────────────────────────────────────────┘
```

### 3.1 为什么不做面板中转层

被否决的方案是让面板监听公网端口、判定后再转发给 127.0.0.1 上的 xray。它能一次解决全部四项且跨平台可单测，但代价不可接受：

- 面板进程成为数据路径的**单点**，面板挂了 = 全员断网；面板重启（SIGHUP）会掐断所有连接。
- 只覆盖 TCP 类传输，mKCP / QUIC 直接绕过。
- 所有流量多一次用户态拷贝，XTLS / splice 优化失效。

生产环境是 Linux + root + systemd，内核手段完全可用，没有理由把面板塞进数据路径。

### 3.2 为什么在线明细用内核连接表而不是访问日志

被否决的方案是解析 `access.log` 推断在线状态。它跨平台且与访问日志共用一套解析，但：

- 在线判定是**推断式**的：一条持续传输但不新建连接的长连接不再产生日志行，会被误判为下线。
- 拿不到每个 IP 的实时网速，也拿不到精确的连接建立时间。
- 无法满足「断链、没有数据传输之后立即释放并发额度」——日志里没有断开事件。

内核连接表（`netlink INET_DIAG`，纯 Go 实现，无外部命令、无新依赖）给出 established 连接的四元组与 `tcp_info` 字节计数，上述三条全部成立。代价是**仅 Linux**：非 Linux 平台通过 build tag 降级为「该能力不可用」，界面明示，不静默返回空数据假装正常。

### 3.3 为什么 IP 归属地用离线库而不是在线查询接口

被否决的方案是调用 iplocation.net 一类的在线接口。它数据更新更及时、还能给出 ASN 等更丰富的信息，但：

- **地区限制根本用不了它。** 生成 xray 路由规则需要的是「江苏省包含哪些 IP 段」（实测 1310 条 CIDR），而在线接口只能回答反方向的「这个 IP 在哪」。没有离线段表就没法生成允许集。
- **在线明细是热路径。** 该页面每 1~2 秒刷新、每个连接一个 IP，走在线查询意味着每次刷新发 N 个外部请求：延迟几十到几百毫秒、免费接口普遍限速（ip-api.com 是 45 次/分钟）、对方不可用功能就没了，而且**要把用户的真实 IP 发给第三方**。
- 本地二分查找是纳秒级，2 MB 内存，零外部依赖。

归属地会随时间失准的问题，用「手动更新 + 每日定时更新」解决，而不是每次都问别人。

#### 实测：免费在线接口在省级精度上并不优于离线库（2026-09-03）

用 8 个已知归属地的 IP 交叉比对，结论推翻了「在线的更新所以更准」这个直觉：

| 服务 | 配额 | 有省份 | 对 114.114.114.114（江苏南京）的判定 |
|---|---|---|---|
| iplocation.net `ip-country` | 无限、免 key | ❌ 只有国家 | China（问不出省） |
| iplocation.net `ip-location` | **10 次/天** | ✅ | Jiangsu ✅ |
| IPinfo Lite | 无限 | ❌ 只有国家 + ASN | — |
| freeipapi.com | 宣称无限 | ✅ | **Shandong 济南** ❌ |
| ip-api.com | 45 次/分钟 | ✅ | **Shandong 济南** ❌ |
| ipwho.is | 1000 次/天、免 key | ✅ | Jiangsu ✅ |
| ip2region（本地） | 无限 | ✅ | 江苏省南京市 ✅ |
| 纯真（本地） | 无限 | ✅ | 江苏省南京市 ✅ |

两个宣称「无限量」的服务，一个只到国家级，另一个把中国最有名的 DNS IP 判成了山东——而该 IP 的 ASN 注册信息写的就是 "Nanjing Jiangsu Province"。**准入判定继续用离线库。**

在线接口仍可作为「点某个 IP 查详情 / 对账」的补充——那是低频的单点操作，不在热路径上，且 ipwho.is 的 1000 次/天足够。

#### 为什么不接 GeoLite2（MaxMind）

实测用真实账号下载：GeoLite2-**City**（唯一带省份的版本）在 CSV 与 mmdb 两种格式下**都返回 HTTP 451**：

```
Downloads of this database from CN are forbidden due to US bulk sensitive data transfer rules
```

同一个 key 下 GeoLite2-Country 与 GeoLite2-ASN 均可正常下载（HTTP 200），且请求来源 IP 是美国——说明限制绑在**账号的注册国家**上，换机器绕不过去。Country 版没有省份，对地区限制没用。

## 4. 不变量

以下五条与分流子系统的四条不变量同级，改动本组功能时都不能削弱。

### 4.1 强制手段绝不重启 xray，且判定必须幂等收敛

并发超额封禁是秒级动作。用「改配置 + 重启 xray」实现会把该机器上**所有用户**踢下线来封一个人，代价完全不成比例。

**判定必须是幂等收敛的**——每轮重新计算应拒绝的集合并施加，而不是只在状态跳变时下发一次。这样漏跑一轮、面板重启、客户端重连都不会让状态跑偏。

#### 实现手段：由 `adrules` 改为 `SOCK_DESTROY`（子项目 4 落地时的修订）

本节原定的做法是 `xray api adrules` 下发带 `ruleTag` 的黑洞规则、`rmrules` 解封。子项目 3 落地后确认内核连接表可以直接 `SOCK_DESTROY` 断开指定 socket，重新比较后改用后者：

| | 运行时路由规则 | `SOCK_DESTROY`（采用） |
|---|---|---|
| 前置条件 | 需要在 `api.services` 里启用 `RoutingService`。**该模板存在用户自改的副本**，改嵌入的默认值对已改过模板的部署无效，会静默失效 | 无。子项目 3 已具备 |
| 客户端表现 | 连接建立、流量进黑洞 → 卡住直到超时（「连上了但打不开」） | 连接被 RST → 「连不上」，更贴近管理员要的"拒绝链接" |
| 与额度计数的关系 | 被封 IP 仍有 established 连接，**依然占着名额**，需要额外状态把它排除 | 连接被断开即从连接表消失，名额自然释放 |
| 规则次序 | `adrules` 追加到规则表末尾，会排在生成的分流规则之后而被绕过，需要额外处理 | 不涉及路由，无次序问题 |
| xray 重启 | 运行时规则全部丢失，必须靠幂等收敛补回 | 无状态，天然收敛 |

代价是**存在一个采样周期的空窗**：超额的 IP 在被断开前最多能正常通信 1 秒（判定周期）。路由规则一旦下发则是立即生效的，但它同样需要先观测到该 IP 才能下发，首轮空窗一样存在——区别只在于重连时路由规则仍然有效而断开需要重来一轮。判定周期取 1 秒即是为此。

两条实现约束：

- **历史条目不得占用名额。** 被拒的 IP 连接已断、在连接表里消失，但界面仍保留它 5 分钟以便管理员看见「谁在被挡」。判定时必须先剔除这些 `Conns == 0` 的条目，否则第一个被拒的 IP 会永久占住一个名额，额度为 1 时所有人（包括他自己）都再也连不上，且自愈不了。
- **次序必须确定。** 面板重启后所有 IP 的首次观测时间相同，此时若排序不稳定，每轮踢掉的人都不一样，结果是谁都用不成。首次观测时间相同时按 IP 字节升序做二次排序。

### 4.2 地区限制用「允许集 + `!` 取反」，且排在生成的分流规则之前

xray 路由**首次匹配即终止，且规则内部没有 NOT 条件**。这排除了把「允许」直接写成一条规则的做法：

- 写成 `{inboundTag:[X], source:[江苏], outboundTag:...}` 排在前面，它会抢在分流规则之前把该用户的流量定死，现有域名分流全部失效；
- 排在后面，则非江苏用户访问被分流的域名时会先命中分流规则走代理出站，**地区限制被静默绕过**。

正确写法是把条件整个取反，规则本身只表达「拒绝」：

```
{ "inboundTag": ["inbound-X"], "source": ["ext:a-ui-geo.dat:!ALLOW-<hash>"], "outboundTag": "a-ui-block" }
```

即「来源**不在**允许省份 → 黑洞」。取反语法已实测生效（§2.1），因此**不需要计算补集**——dat 里存正向的允许集即可。

注入顺序改为：

```
模板原有规则 → 地区规则 → block 规则 → proxy 规则
```

这是对「一律 append 到末尾」的一处**受控例外**：地区规则仍追加在模板原有规则之后（模板里屏蔽私网 / BT 的安全规则保持更高优先级），只是排在本项目生成的其余规则之前。理由是地区限制属于准入判定，逻辑上必须先于任何分流决策。

**IPv6 不会自动 fail closed，必须显式处理。** 实测确认：允许集只含 IPv4 时，IPv6 来源在 `!` 取反下被**放行**——匹配器不会拿 v6 地址去比对一个没有 v6 条目的集合。

处理方式是**两层**。主手段是启用地区限制的入站把 `listen` 限定为 IPv4（`0.0.0.0`），客户端根本无法从 IPv6 连上来，既不需要额外数据也不会误伤。但管理员随时可能把 `listen` 改回留空（双栈），所以仍然生成一条 `::/0` 的拒绝规则作为纵深防御，IPv6 那条在前：

```
{ "inboundTag": ["inbound-X"], "source": ["::/0"],                             "outboundTag": "a-ui-block" }
{ "inboundTag": ["inbound-X"], "source": ["ext:a-ui-geo.dat:!ALLOW-<hash>"],   "outboundTag": "a-ui-block" }
```

只做 `listen` 限定而漏掉第二条规则的后果是：某天有人把 `listen` 改回留空，地区限制就形同虚设——客户端开一个 IPv6 即可绕过，且配置校验通过、面板显示一切正常。表单上必须明确提示「启用地区限制后，该入站只监听 IPv4，通过 IPv6 连接的客户端将被拒绝」。

### 4.3 允许集写进自定义 geo dat，并把内容哈希嵌进 `ruleTag`

省份 CIDR 不内联进 `bin/config.json`。实测量级：江苏省 1310 条 CIDR（约 13 KB），江苏+河南 1955 条，广东省 2915 条——单看并不大，但那个 10 秒重启消费 cron 每轮都要重新生成整份配置并逐字节比较，多入站会成倍放大。改为生成 `bin/a-ui-geo.dat`（v2ray GeoIP 的 protobuf 格式，字段为 `CIDR{ip=1,prefix=2}` / `GeoIP{country_code=1,cidr=2}` / `GeoIPList{entry=1}`，手写编码约几十行，零新依赖），配置里只写一个 `ext:` 引用。

**dat 文件的内容变化不体现在配置字节里，`Config.Equals` 察觉不到，xray 不会重新加载。** 解法是把 dat 内容的哈希嵌进规则的 `ruleTag`：`a-ui-geo-<inboundId>-<hash8>`。哈希变则配置字节变则重启，重启逻辑天然正确，不必为 dat 单独造一套变更检测。`ruleTag` 在静态配置中合法（已实测）。

两条实现约束：

- dat 内的 tag 查找**大小写不敏感**（写 `ALLOWV4`、配置里引用 `allowv4` 可以命中）。tag 统一用大写生成，避免两套写法并存。
- 相同省份组合的多个入站**共用同一个 tag**，按省份集合去重，避免 dat 里出现大量重复条目。

### 4.4 不给客户端加 `email`

访问日志行里已有 `[inbound-10011 >> direct]`，用入站 tag 就能关联到人。加 `email` 要改动 `settings` JSON 的结构，收益只是多一份与入站级重复的统计。

### 4.5 tc 只在有限速配置时接管 root qdisc

`tc` 限速要接管网卡的 root qdisc，**配错会影响整机全部流量，包括 SSH**。落地时的六条约束：

1. **全部入站都没配限速时，一条 tc 命令都不执行。** 管理员可能自己配了 fq_codel / cake，擅自接管会把他的配置冲掉。判断「限速是否正由本面板接管」靠专属 ifb 设备 `a-ui-ifb0` 是否存在——面板重启后内存状态没了，内核里的规则还在，只有这个标记能把「配置已清空、规则该拆」与「本来就没下过」区分开。
2. **未分类流量落到无限速的默认 class**（`htb default 9999`，`rate 10000mbit`）。**SSH 走的就是这一类。** 这是整个功能的安全底线。
3. **整树推倒重建，不做增量 diff。** 只有重建才是真正幂等的：漏跑一轮、状态被外部改动都能自愈。代价是重建瞬间流量不受整形（不是丢弃）。
4. **先建 ifb 的队列树，最后才装 ingress 重定向。** 反过来的话，中间那一小段时间里全部入站流量会被送进一个还没配好的设备。
5. **自动撤销（新增）。** 下发一套**运行中新产生**的限速配置后，若 2 分钟内没有收到任何已登录的面板请求，自动拆除全部规则并记住这套配置的哈希，改之前不再重试。确认信号打在 `BaseController.checkLogin` 上，覆盖前端每 2 秒轮询的 `/server/status`。面板启动时把库里既有配置重新下发**不武装**该机制——那是一套已经在用的配置。
6. **两个手动清除入口。** 面板设置页有按钮；更关键的是命令行 `./a-ui tc-clear`——限速配错时面板本身就访问不到了，界面上的按钮没有意义，从服务商控制台登录进来执行这条命令才是真正的救援路径。它不连数据库、不启动面板，探测不到网卡时也至少把 ifb 拆掉。

限速的方向映射（搞反就是限错了人）：**下行**（服务端→客户端）= 主网卡 egress，按**源端口**分类；**上行**（客户端→服务端）= 主网卡 ingress，重定向到 ifb 后按**目的端口**分类。IPv4 与 IPv6 各下一条 u32 filter——`protocol ip` 只匹配 IPv4，漏掉 v6 的话 IPv6 客户端完全不受限速。

## 6. 已确认的语义决策

与管理员逐条确认，是后续实现的前提：

1. **并发的计数口径是「同时在线的不同来源 IP 数」**，不是 TCP 连接数（一个浏览器就会开几十条连接，按连接数设 1 会把用户自己卡死）。
2. **超额时拒绝后来的 IP**（先来后到），不踢已在线的人；管理员可在展开行里手动踢人腾出额度。
3. **限速上行 / 下行分开设，单位 Mbps**。上行需要 ifb 虚拟网卡重定向。
4. **续期语义：未到期则在原到期时间上叠加，已过期则从今天算起。** 同时自动重新启用被停用的入站、重置已用流量，并且必须弹窗确认。除预设天数外提供自定义日期。
5. **IP 库精度为「全球国家 + 中国省市」，双源并存**：
   - `ip2region`（`ipv4_source.txt`，Apache-2.0 OR MIT）：2.1 MB，21.6 万段。仓库跟踪一份生成好的 `bin/ipdb.dat`，开箱可用。
   - `纯真 IP 库`（`qqwry.dat`，GitHub 每日镜像）：生成后 2.5 MB，26.2 万段（原始 149 万条记录）。**不进仓库**（再分发条款不明确），由管理员配置地址后下载到 `bin/ipdb-qqwry.dat`。

   **合并策略是并集**：任一数据源认为某段属于所选省份就放行。对用户而言「本该能连却连不上」比「本不该连却连上了」严重得多。实测江苏省：ip2region 1310 条 CIDR + 纯真 866 条 → 并集 1893 条。

   **更新用「每天几点」而不是「隔几天」**（`ipdbUpdateTime`，格式 HH:MM，留空关闭）。管理员能把它放进自己的低谷时段，更新时机可预期；自检任务每 10 分钟跑一次，与域名组订阅同一套机制。单个源失败不影响另一个源。
6. **前置层为客户端直连**（域名只做伪装，无 CDN / 反代），来源 IP 真实可见；若将来上 CDN，§3.2 的内核连接表方案会失效——届时只能退回 xray 层（ws 入站会读 `X-Forwarded-For`）。

## 7. 风险登记

| 风险 | 影响 | 缓解 |
|---|---|---|
| netlink 收发层无法在开发机验证 | 生产上才暴露问题 | 报文编解码与聚合算速率全部做成纯函数并单测；收发层压到 ~40 行；必须在 Linux 生产机上实测 |
| 用 UDP 传输的入站看不到在线明细 | 管理员误以为没人在线 | 接口返回 `supported=false` + `reason`，界面显式提示；绝不返回空列表冒充"无人在线" |
| tc 配错影响整机流量含 SSH | 失联 | §4.5 的六条约束；2 分钟无面板请求即自动撤销；命令行救援入口 `./a-ui tc-clear`。**仍须先在能从控制台救回的机器上验证** |
| tc 执行层无法在开发机验证 | 生产上才暴露 | 命令生成、状态机、自动撤销全部做成纯逻辑并单测（22 个用例）；执行层压到约 60 行 |
| 并发误封 | 用户上不了网且难自查 | 拒绝动作记 `logger.Warning`（按 IP 去重，避免反复重连刷屏）；展开行用「超额被拒」标记显示当前被挡的 IP，连接断开后仍保留 5 分钟 |
| 每秒一次的判定任务 panic | 面板整体挂掉 | `ConcurrencyJob.Run` 首行 `defer common.Recover`；无受限入站时直接返回，不碰内核 |
| 访问日志体积 | 磁盘写满 | 独立 SQLite 库；保留期可配（默认 7 天，不允许填 0）；日志文件超 16 MB 消费完即截断；剩余磁盘低于 512 MB 停写并告警；**默认关闭，需管理员显式开启** |
| 删除入站后访问日志残留 | SQLite 复用 id，新用户看到上一个人的记录 | `DelInbound` 主动清理；清理失败只告警不阻断（避免日志库故障把管理员卡在删不掉入站的状态），由启动时与每小时一次的 `PruneOrphans` 兜底，残留窗口最多一小时 |
| 定时任务 panic 杀进程 | 面板整体挂掉 | `Server.Start()` 的 cron 没有 panic 恢复；本组新增的所有 cron 任务必须自带 `common.Recover` |
| 地区规则漏掉 IPv6 那条 | 限制被静默绕过 | §4.2；生成器必须成对输出两条规则，测试对两条都断言 |
| SQLite 自增 id 复用 | 旧引用绑到新记录 | 本组功能全部按入站 id 建模，新增任何存 id 外键的表都要照分流子系统那样加 `Check*Refs` 守卫 |
